# MyBatis

## SQL 映射与参数绑定（未学习）

### 集合参数如何安全映射为批量条件（未学习）

1. 目标：将运行时集合转换为批量筛选条件，并保持参数值与 SQL 结构分离。
2. 前提：集合元素是参数值，SQL 模板由映射文件定义。
3. 推导 1：动态遍历节点为每个元素生成一个占位参数。
4. 推导 2：占位参数由驱动绑定值，避免把值拼接进 SQL 文本。
5. 结论：使用集合遍历和参数绑定表达批量条件，可兼顾安全性与可维护性。
6. 边界：空集合的 SQL 语法和数据库限制需在调用层或动态节点中单独处理。

### 动态 SQL 如何保持结构与参数分离（未学习）

1. 目标：按条件组合查询结构，同时防止用户输入改变 SQL 语法。
2. 前提：条件是否存在属于控制信息，条件值属于数据。
3. 推导 1：动态标签只决定片段是否出现或如何连接。
4. 推导 2：条件值始终通过占位符绑定，不参与标签文本拼接。
5. 结论：把结构决策交给动态 SQL，把数据交给参数绑定，可保持边界清晰。
6. 边界：动态列名、表名等标识符无法直接参数化，必须使用受控白名单映射。

### 结果映射如何维护列与对象契约（未学习）

1. 目标：将查询列稳定装配为对象属性，并使结构变化可被发现。
2. 前提：列名、别名、类型与对象属性构成映射契约。
3. 推导 1：显式结果映射声明列到属性及类型的对应关系。
4. 推导 2：查询增加连接或嵌套对象时，映射可表达层级和复用关系。
5. 结论：显式结果映射能降低列名差异和隐式推断带来的不确定性。
6. 边界：数据库返回类型与目标属性不兼容时仍需类型处理器或转换逻辑。

### SQL 片段复用如何控制变更影响（未学习）

1. 目标：复用稳定的 SQL 片段，同时限制修改对调用方的影响范围。
2. 前提：片段被多个语句引用，且其列别名和条件语义具有契约。
3. 推导 1：将共享列集或过滤条件抽取为可引用片段。
4. 推导 2：引用方组合片段并补充自身特有条件，避免复制文本。
5. 结论：集中维护共享片段可减少重复修改，但必须维护片段契约。
6. 边界：片段内部别名、参数名或连接上下文变化可能破坏调用方。

## ORM 框架与数据库方言（未学习）

### 复杂查询何时保留手写 SQL（未学习）

1. 目标：在抽象便利性与查询可控性之间选择合适的实现方式。
2. 前提：查询可能包含窗口、递归、方言函数或精细的执行顺序要求。
3. 推导 1：当抽象层无法表达语义时，继续堆叠条件会降低可读性和可验证性。
4. 推导 2：手写 SQL 可直接控制投影、连接、排序及数据库特性。
5. 结论：复杂或方言相关查询宜保留在自定义映射语句中，并复用结果契约。
6. 边界：手写 SQL 增加方言耦合，迁移时需重新评估语法和执行计划。

### 映射层如何隔离数据库方言（未学习）

1. 目标：让上层调用依赖稳定接口，而非依赖某数据库的 SQL 语法。
2. 前提：同一业务语义可能在不同数据库使用不同表达式。
3. 推导 1：把方言语句集中在映射层或按数据库分支组织。
4. 推导 2：上层只依赖参数对象和结果对象契约，选择方言由配置或装配决定。
5. 结论：将方言差异限制在映射边界，可降低迁移和测试成本。
6. 边界：数据类型、排序规则或事务语义差异可能仍需上层显式协调。
