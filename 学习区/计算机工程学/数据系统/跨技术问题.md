# 跨技术问题

## 批量关系查询的正确性与性能（未学习）

### 批量取每组首条记录的通用问题（未学习）

1. 目标：在一次查询中为多个分组各取一条满足条件的代表记录。
2. 前提：每条记录有分组键，且“首条”必须由稳定排序规则定义。
3. 推导 1：先限定候选分组和业务过滤条件，再在每组内按排序选取首行。
4. 推导 2：排序键不唯一时追加唯一键，避免同组结果随执行计划改变。
5. 结论：分组取首行的正确性取决于过滤范围和确定性排序的共同约束。
6. 边界：不同数据库对分组首行语法支持不同，迁移时需改写实现。

### 过滤顺序如何影响结果正确性（未学习）

1. 目标：确保代表记录是在合法候选集中选出，而不是选出后再错误剔除。
2. 前提：过滤条件可能包含记录状态、关联对象状态和权限规则。
3. 推导 1：将决定可见性的条件纳入候选集，减少不合格记录参与排序或分组。
4. 推导 2：若先选首行再过滤，首行被剔除后可能造成分组缺失。
5. 结论：先完成语义过滤再执行分组选取，才能保持结果正确。
6. 边界：优化器可能重排等价谓词，但不能改变 SQL 定义的结果语义。

### 多条件可见性规则如何进入索引设计（未学习）

1. 目标：让包含状态、权限和关联条件的查询获得可接受的访问成本。
2. 前提：索引只能直接利用其列和谓词，无法替代复杂业务判定。
3. 推导 1：识别高频等值条件、范围条件和排序键，作为索引候选顺序。
4. 推导 2：对低选择性或依赖连接的条件，结合执行计划评估是否值得纳入索引。
5. 结论：索引设计应围绕完整查询路径，而非只针对单个过滤字段。
6. 边界：数据分布、统计信息和写入成本变化会改变最优索引方案。

### 宽行投影、回表与网络传输的权衡（未学习）

1. 目标：在返回完整对象与控制查询资源之间取得平衡。
2. 前提：宽投影增加页访问、回表、排序内存和结果传输成本。
3. 推导 1：先用窄投影完成筛选和定位，再按需获取详细列可减少中间成本。
4. 推导 2：覆盖索引可避免回表，但索引体积和维护成本随覆盖列增加。
5. 结论：投影列应与使用场景匹配，不能仅因查询方便而长期选择全列。
6. 边界：一次确需完整实体时，拆分查询可能增加往返次数和一致性协调成本。

### 如何用执行计划验证优化假设（未学习）

1. 目标：用可重复证据判断索引或 SQL 改写是否真正改善查询。
2. 前提：执行计划反映优化器在特定统计信息、参数和数据量下的选择。
3. 推导 1：先记录基线的耗时、扫描行数、排序和缓冲区访问。
4. 推导 2：应用单项改动后，在相同数据和参数下比较实际执行指标。
5. 结论：优化结论必须由对照执行计划和运行指标共同支持。
6. 边界：缓存状态、并发负载和参数分布变化可能使单次结果失真。
