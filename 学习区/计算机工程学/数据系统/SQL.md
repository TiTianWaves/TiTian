# SQL

## 关系模型与值语义

### 表、行与列的关系

1. 目标：建立表、行、列之间的关系模型。
2. 前提：关系由属性定义，元组承载属性值。
3. 推导 1：表的列集合定义每行允许出现的属性及其类型。
4. 推导 2：一行是这些列在一次记录中的联合取值，行集合构成关系实例。
5. 结论：查询操作以关系为输入并产生新的关系，不依赖物理存储顺序。
6. 边界：具体数据库可扩展类型和物理组织，但不改变关系结果的逻辑定义。

### 主键、外键与唯一性

1. 目标：理解约束如何维护标识和引用关系。
2. 前提：主键要求候选值唯一且非空，外键引用被约束关系中的键。
3. 推导 1：主键约束把每行映射到稳定标识，避免同一关系内的歧义。
4. 推导 2：外键约束要求引用值在被引用表存在或按规则取空，从而限制无效关联。
5. 结论：唯一性与引用完整性由约束声明，比应用层约定更能持续阻止非法状态。
6. 边界：级联动作、可空外键和约束检查时机由数据库实现和声明选项决定。

### NULL 与三值逻辑

1. 目标：正确推导包含 NULL 的条件结果。
2. 前提：NULL 表示缺失或未知，不等同于零值或空字符串。
3. 推导 1：涉及 NULL 的比较通常得到 UNKNOWN，而非 TRUE 或 FALSE。
4. 推导 2：WHERE 只保留 TRUE，FALSE 与 UNKNOWN 都被过滤。
5. 结论：判断缺失值必须使用 IS NULL 或 IS NOT NULL，并审慎组合 AND、OR、NOT。
6. 边界：聚合、排序和唯一约束对 NULL 的处理存在数据库方言差异。

## 查询逻辑处理

### FROM、JOIN、WHERE 的逻辑顺序

1. 目标：按逻辑阶段推导连接和过滤结果。
2. 前提：FROM 先形成表源，JOIN 扩展或匹配行，WHERE 再筛选组合结果。
3. 推导 1：连接条件决定哪些行被配对，以及外连接是否保留未匹配行。
4. 推导 2：WHERE 作用于连接后的行，条件不满足的组合被移除。
5. 结论：把条件放在 ON 或 WHERE 可能改变外连接结果，即使文本条件相同。
6. 边界：优化器可重排物理执行步骤，但须保持逻辑等价结果。

### DISTINCT、GROUP BY 与重复行

1. 目标：区分去重和分组聚合的结果语义。
2. 前提：连接或投影可能产生重复的逻辑行。
3. 推导 1：DISTINCT 对投影后的整行值去重，不计算组内统计。
4. 推导 2：GROUP BY 按分组键组织行，并要求非键列通过聚合或函数确定。
5. 结论：只需消除重复时用 DISTINCT，需要组内计算时用 GROUP BY。
6. 边界：NULL 的分组、排序和相等判断遵循三值逻辑及具体实现规则。

### ORDER BY、LIMIT 与结果确定性

1. 目标：保证分页或截取结果具有可重复顺序。
2. 前提：关系本身无固有顺序，只有 ORDER BY 声明顺序要求。
3. 推导 1：LIMIT 在排序结果上截取行，未排序时截取对象可随计划变化。
4. 推导 2：排序键出现并列时，数据库可任意排列并列行。
5. 结论：分页应使用能唯一确定顺序的复合 ORDER BY，并配合稳定边界条件。
6. 边界：并发插入、更新或删除仍可能改变跨页可见集合，需要一致性策略。

## 关系查询与分组结果

### 批量 IN 查询如何表达一组待查询用户

1. 目标：用单条查询表达对一组键的筛选。
2. 前提：IN 将左侧表达式与候选值集合逐一比较。
3. 推导 1：优化器可把 IN 转换为多次等值访问、范围访问或其他等价计划。
4. 推导 2：空集合需由调用方处理，因为不同驱动对空 IN 列表的语法支持不一。
5. 结论：批量键查询减少往返并保持集合语义，但仍受列表规模和选择性影响。
6. 边界：候选值含 NULL 时结果可能为 UNKNOWN；超大集合应考虑临时关系或批量分段。

### 连接类型如何影响结果集

1. 目标：根据业务保留需求选择连接类型。
2. 前提：INNER JOIN 只保留两侧匹配行，外连接额外保留一侧未匹配行。
3. 推导 1：LEFT JOIN 以左表为保留集合，右侧缺失值补为 NULL。
4. 推导 2：对右表列的 WHERE 条件会过滤 NULL 补位行，可能使 LEFT JOIN 退化为 INNER JOIN。
5. 结论：连接类型与条件位置共同决定结果是否保留缺失关联。
6. 边界：多对多连接会放大行数，需通过约束、去重或聚合恢复预期基数。

### 过滤排序后如何得到每组一行

1. 目标：在每个分组中选出满足排序规则的代表行。
2. 前提：先确定可见行集合，再定义组键和组内全序。
3. 推导 1：过滤移除不可选行，排序为组内候选建立优先级。
4. 推导 2：窗口函数、相关子查询或方言特性可依据该优先级保留排名第一行。
5. 结论：每组一行问题必须同时声明过滤条件、分组键和确定性排序键。
6. 边界：排序键并列时若无唯一决胜列，代表行不稳定；没有候选行的组不会产生结果。

## 索引与执行计划基础

### 索引作为访问路径

1. 目标：理解索引如何减少读取候选行的成本。
2. 前提：索引维护键值到行位置或行标识的有序或可检索结构。
3. 推导 1：条件命中索引前缀时，可跳过不符合范围的页面或记录。
4. 推导 2：命中后仍可能需要回表读取未包含的列。
5. 结论：索引是可选访问路径，不改变 SQL 逻辑结果。
6. 边界：低选择性、表达式不匹配或统计信息失真时，优化器可能选择全表扫描。

### 选择性与扫描范围

1. 目标：用选择性评估索引过滤价值。
2. 前提：选择性描述谓词筛掉数据的比例，扫描范围描述需要访问的键区间。
3. 推导 1：高选择性等值条件通常形成较小候选集，降低随机读取。
4. 推导 2：范围扩大或低选择性时，索引访问的回表成本可能超过顺序扫描。
5. 结论：索引收益取决于数据分布、谓词和返回列的联合成本。
6. 边界：选择性会随数据增长和参数变化漂移，不能仅凭单次样本判断。

### 执行计划中的扫描、排序与连接

1. 目标：从执行计划定位主要访问和中间结果成本。
2. 前提：计划由扫描、连接、过滤、排序等算子组成，并带有估算基数与成本。
3. 推导 1：扫描算子决定数据进入后续算子的方式和规模。
4. 推导 2：连接与排序的代价受输入基数、内存和可用索引影响。
5. 结论：阅读计划应比较估算与实际行数，并关注高成本或大量回表算子。
6. 边界：不同数据库计划格式和成本单位不可直接横向比较。

## 查询语义边界

### ORDER BY 如何决定最新记录

1. 目标：明确“最新”必须由可验证的排序依据定义。
2. 前提：时间列表达业务时间，递增标识可作为并列时的决胜键。
3. 推导 1：按时间降序可优先选择时间值最大的记录。
4. 推导 2：时间相同或缺失时，追加唯一键才能形成稳定全序。
5. 结论：最新记录是排序规则的结果，不是表中物理最后一行。
6. 边界：时钟回拨、延迟写入和不同时间语义会使单一时间列不能代表业务新旧。
