# 计算机工程学学习领域协议

## 领域定位

1. 本文件是计算机工程学学习领域的专属协议，不是工作区项目协议，也不记录仓库职责、代码事实或业务数据。
2. 它由用户确认领域规则后，由 Agent 代写和维护；通用学习流程、笔记写法和授权边界以根目录《学习协作协议》为准。

## 领域目录与归属

1. 本领域记录计算机工程学的技术知识；技术笔记文件名同时作为笔记根节点。
2. 笔记使用 `# 笔记名`、`## 模块`、`### 小节` 组织；模块和小节按学习内容生长，不预建完整知识树。
3. 软件工程按语言子目录组织，例如 `软件工程/Java/`；语言无关主题保留在 `软件工程/`。
4. 数据库及其访问层（包括 MyBatis、MyBatis-Plus）统一聚合在 `数据系统/`；跨技术工程问题统一写入 `数据系统/跨技术问题.md`。

## 知识复用与领域边界

1. 单一技术的机制、语义和边界写入该技术的专属笔记，并通过 Markdown 标题链接与其他节点建立连接。
2. 多个技术共同构成独立工程问题时，在 `数据系统/跨技术问题.md` 中建立跨技术节点；该节点记录组合后的机制、方案和代价，不替代专属笔记。

## 数据库学习主线

1. 数据库学习采用“SQL 通用基础 + MySQL 主力数据库 + 其他数据库差异”的分层标准。
2. SQL 通用基础记录跨关系型数据库稳定成立的语义、查询结构、事务概念、约束、索引原理和执行计划阅读方法。
3. MySQL 作为主力数据库，记录相对 SQL 通用基础的实现机制、执行链、存储引擎、索引、事务、锁、日志、复制、运维和工程问题，并以当前 MySQL 版本和 InnoDB 行为注明边界。
4. 其他关系型数据库不重复建设 SQL 通用能力，也不重复记录与 MySQL 相同的能力；只记录 MySQL 没有的增强能力，以及该数据库相对 MySQL 缺失或语义不同的能力，并明确差异边界。
5. 数据库差异节点优先回答能力解决的问题、与 SQL/MySQL 的连接或差异、迁移代价和适用边界，不扩展为另一套完整数据库教程。

## 数据库目录聚合

1. `数据系统/` 是本领域的数据库目录，统一承载 `SQL.md`、`MySQL.md`、其他数据库特性笔记及 MyBatis、MyBatis-Plus 访问层笔记。
2. 数据库目录中的技术笔记按技术分工，跨技术问题集中在 `跨技术问题.md`，不在软件工程语言目录重复建立。
