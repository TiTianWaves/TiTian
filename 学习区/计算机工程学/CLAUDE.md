# 计算机工程学领域协议

领域:计算机工程学。领域规则逐节添加;当前仅有「大纲」一节。

## 大纲

### 技术笔记(首次涉及某技术)

- 待学习知识点指向无笔记的技术时:生成该技术的完整一级与二级大纲,创建笔记文件,正文留空。
- 一级大纲 = 该技术的稳定认知边界:架构与机制、核心语义、运行路径、设计决策、工程边界、工程问题路径;
- 二级大纲 = 每个一级板块下的稳定主题;
- 不生成三级及以下标题,三级及以下在知识点落位时按需生长;
- 大纲经用户确认后作为该技术的知识地图;
- 完整性自检:生成后做「工程问题 → 大纲位置」映射自检,重要工程问题(穿透/击穿/雪崩、缓存一致性、分布式锁、主从/哨兵/Cluster、持久化、淘汰、过期风暴、大Key热Key、连接池、序列化、慢查询)必须在 L1/L2 有位置;找不到位置的工程问题 = 大纲缺板块,补板块。

### 聚合文件(跨技术工程问题)

- 跨多个技术的工程问题(如 双写不一致 涉及 Redis、Redisson、MySQL)不放入单技术笔记,统一聚合于 `数据系统/跨技术问题.md`(一个聚合文件,每个问题一节);按需生长,不预建。
- 每节结构:方案谱系(多种方案并列,各自适用与代价)→ 技术栈映射(链接技术笔记机制章节,不重复写)→ 边界与代价。

### 目录组织

- 软件工程按语言子目录组织(如 `Java/`;未来 Python/、Rust/ 各建子目录),语言特定笔记入对应子目录;跨语言通用主题(如 设计模式)放顶层。

### 知识点落位归属

- 待学习知识点行的归属判断:跨技术 → 聚合文件(`数据系统/跨技术问题.md`);单技术 → 技术笔记大纲位置。

## 笔记组织(三阶段)

适用于熟练/精通级;了解级直接按三要素(是什么 / 何时用 / 设计权衡)写入。

### 阶段一:边界确认

- Agent 给出前置知识候选清单(为掌握该知识点,需要先掌握什么);
- 用户按自己的掌握能力逐项回答(已掌握 / 部分掌握 / 未掌握);
- 未掌握项纳入本次学习边界:先讲前置,或标注待补;
- 前置知识边界有界,确认后固定。

### 阶段二:组织

- 由 Agent 直接安排非叶子节点的层级与顺序(前置先行;顺序不当 = 认知负担);
- 叶子判定:节点能用工程问题推导讲清一个完整知识点 = 叶子;需要前置知识或细分 → 继续下钻。

### 阶段三:叶子写法(内容 → 读 → 骨架推导 → 打分)

1. AI 给出叶子内容(知识点材料:机制、用法、坑、边界,按评级详略);
2. 用户阅读并提问,Agent 答疑;用户自认读懂后进入推导;
3. AI 给出推导骨架(工程问题 + 子问题阶梯 + 结论位 + 边界位);
4. 用户按骨架独立推导——推导是用户的动作,AI 不产出推导;
5. AI 打分(1-5,先入评分列)并给出反馈意见(断点、跳步、想当然、错误),不重写;
6. 盲区处理:推导中卡住 → 识别盲区 → 转化为学习议题(一个具体可研究的问题)→ 查资料(或 AI 提供入口)→ 回来继续推导;
7. 推导只证明能做例题,不代表举一反三;后续仍有按评级的应用/设计题考核。
